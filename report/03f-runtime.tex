\subsection{Runtime and scalability}\label{sec:runtime}

% Sources: one fit at the rule's setting, tuning excluded; results/datasets/{make_moons,wine}_results.csv
% (fit_seconds, ari). No method reaches ARI > 0.7 at the rule's setting on D4 (results/hotspot/shared_rule.csv),
% D5 (results/datasets/fashion_mnist_results.csv) or D8 (results/hdb_resale/comparison.csv); D2 and D3 have no labels.
% ms per 1,000 points = fit seconds / n x 10^6.
Runtime is compared only where a method reaches ARI $>0.7$, which happens on D1 and D6 only; it is one
fit's time per 1{,}000 points at the rule's setting (Table~\ref{tab:runtime}).
In the case where ARI $>0.9$, only one method qualifies on each dataset: Spectral on D1 (244\,ms) and GMM
on D6 (37\,ms). In the case where ARI $>0.7$, the ranking from fastest is HDBSCAN (36\,ms), then Spectral
(244\,ms) on D1, and K-Means++ (34\,ms), then GMM (37\,ms), then Agglomerative (79\,ms) on D6.
